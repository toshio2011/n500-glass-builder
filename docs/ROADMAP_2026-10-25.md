# N500 Glass TV — Master Development Roadmap

**Updated:** 25 October 2026  
**Project:** [toshio2011/n500-glass-builder](https://github.com/toshio2011/n500-glass-builder)  
**Base:** [aqmangge/glass-tv-home](https://github.com/aqmangge/glass-tv-home) pinned to commit `bfa48608c79074d5e57b9efeb098a64e7601e3cd` (2.6.0)  
**Installed package:** `com.n500.glasstvhome`; original Java namespace remains `com.gathin.tvhome`  
**Primary devices:** N500/N500Pro projector, projector remote, Android phone (dedicated companion APK, optional browser/Termux tools). No desktop required.

> **Status note:** This is the agreed *plan*, not a claim of implemented features. Features marked exploratory need hardware/firmware validation before implementation.

## Goal

A beautiful, responsive, ad-free, **totally configurable** smart-projector Home that keeps Glass TV's current glass aesthetic and can optionally become an all-in-one entertainment dashboard.

**User controls the experience, not the launcher**:
- All new modules **OFF by default**, so the proven Home is not disturbed.
- Enable/disable modules, select variants, arrange/reorder rows, choose which apps participate, adjust position, size, density, refresh and visuals.
- Projector D-pad/OK/BACK always works; companion phone APK is an additional controller and browser controls remain optional. Buttons must not block essential projector functions.
- Presets: Original Glass, Minimal, Streaming, Family, Cinema, Custom. Individual widgets can override a preset.
- Preferences persist over reboot and support backup/export/import (no credentials included by default).
- Lightweight/offline-friendly with graceful fallback for missing data/permissions.

```sh

adb shell pm enable --user 0 com.google.android.tvlauncher
adb shell am start -n com.gathin.tvhome/.MainActivity
```

Keep both fallbacks installed until updater, rollback and safe-home tests are proven.

## Phase 0 — Fix update/recovery foundation (P0, prerequisite)

### 0.1 Stable app signing
- Current builder generates a debug signing key on the CI runner; a different runner can produce an incompatible signature.
- Generate and store a persistent signing identity in **protected GitHub Actions secrets**, never commit its private key to this public repository.
- Compare the **existing installed APK certificate** against the stable new signer before publishing any update.
- **Critical:** if the installed debug-signed APK uses a different key, an in-place update is impossible without the original key; plan a separate-package migration/backup or explicitly user-approved uninstall and restore, never claim preferences survive.
- Add versioning, APK signature/cert fingerprint inspection, sha256, reproducible provenance and release notes.

### 0.2 Safe builds and upgrades
- Refactor builder from one large ad-hoc patch to modular, versioned patch modules or a maintained fork with a pinned upstream tag.
- CI compile/test lint and package ID verification; keep original app separately installed and unmodified.
- Automated smoke checks; rollback release artifacts; no incompatible upstream OTA.
- Add a preflight page/command that confirms ADB connection, enabled Home candidates and fallback access.
- Reboot only after healthy Home, Settings and app navigation confirmed; never auto-disable a launcher on upgrade.

## Phase 1 — Customization and weather (P1)

### 1.1 Modular Home layout
- Maintain current clock, AQI/weather chip, scenic wallpaper, prayer widget, Inputs and glass dock.
- Settings > Home Modules: master feature toggles, widget/order/position, focus order, margins, size, row count, background blur/opacity, compact/comfortable density and visibility rules.
- Fully remote-operable configuration with preview/apply/cancel/reset; preset chooser and optional phone control.
- Avoid fixed-height pages that crop content; scroll smoothly with understandable partial-row peek (existing scroll behavior is intentional).
- Keep read-only screenshots/preview for reviewing layouts across common projector resolutions.

### 1.2 Mini forecast row
Existing Glass TV Weather Dashboard documents **12-hour forecast and 7-day outlook**; inspect source and reuse its data/repository/cache, not a parallel weather API.
- Display modes: **Original current-weather chip / Mini forecast only / Both / Off**.
- Forecast lengths: 3 / 5 / 7 days as supported by valid data; compact strip, mini glass cards or expanded row.
- Day label, condition icon, high/low, rainfall chance individually toggleable; optional AQI indicator.
- Position: beneath clock/weather, top widget lane or a configurable full row.
- Refresh policy, loading/empty/offline states, location selection; units °C/°F where meaningful.
- D-pad forecast focus opens existing full Weather Dashboard; Weather icon preserved in Original mode.

## Phase 2 — Universal Streaming Hub (P1/P2)

**Not hardcoded to Netflix/YouTube/Loklok. Discover *all installed compatible apps*.** This includes Netflix, YouTube, Prime Video, Disney+, iQIYI, Viu, Loklok, SmartTube, Plex, Kodi, Jellyfin, Stremio or anything else where legitimate data is published.

### 2.1 Discover and validate data sources
- Enumerate eligible packages/launcher activities with Android package visibility constraints respected.
- Probe Android TV Preview Channels / Watch Next / TV Provider access and relevant ContentProviders, public/deep-link intents, MediaSession/notifications *only with required permissions and user consent*.
- Test per-app on actual N500 to build a **capability matrix**: Installed? Publishes channel? Continue Watching? Recommendations? Deep-link direct play? Unsupported?
- Some services keep history/private feeds inside their apps: **cannot promise a universal watch-history scraper**. No accessibility scraping, DRM bypass or fabricated recommendations.
- Graceful fallbacks: show a launch-app card / source-specific row / empty state where real titles unavailable. Hidden unsupported rows by default.

### 2.2 Streaming rows and options
- Modules: **Continue Watching**, Recommended, Recently Watched (only when real data exists), Trending, New Releases, Watchlist, per-app collections.
- Toggle *each row* and *each app*. Unified mixed rows or separated by app; filter, reorder, hide titles, edit displayed row names.
- Source badges, poster/landscape/compact variants, number of visible cards, optional progress, source name, title labels and content sensitivity filters.
- Poster action: launch **deep link to title** if valid; otherwise launch app, clearly indicating that fallback.
- Incremental provider refresh and local poster caching; strict image-size and storage limits; no network on render thread.
- Explicit refresh button and offline behavior; optionally remember selected sources/progress locally but do not infer watch time from app launch alone.
- Start with permissions-free/low-privilege prototypes. Do not request invasive capabilities merely to fill a row.

## Phase 3 — Android phone APK, local controls, remote and focus key (P1/P2)

**Confirmed deliverable: a separate installable Android phone APK, not merely a browser controller.** Keep the browser controller as a no-install alternative. The phone app is NOT built yet.

### 3.0 N500 Glass TV Remote — Android phone APK
- Create a dedicated phone project/module built into an `.apk` using GitHub Actions, with signed versioned releases and download instructions for an Android phone (including Android 16); no laptop needed.
- Device-discovery and **QR/code pairing** with the projector on the same Wi-Fi. Store only a per-device revocable pairing token, use authenticated LAN endpoints, and never expose unauthenticated controls to the Internet.
- Primary screen: touch D-pad, OK, Back, Home, volume (subject to OS support), app launcher and input switching where available.
- Settings pages: wallpapers and uploads, weather mode (Original/Mini/Both/Off), 3/5/7-day options, dock/row order, streaming source and row toggles, themes, presets, and status.
- Include an integrated **Multi-View control panel** for capabilities proven on the N500; do not claim unsupported HDMI PiP or app compositing.
- Include an optional focus shortcut/control **only if firmware exposes a supported API**; optical focus remains functional through the original remote.
- The projector launcher must offer a minimal, authenticated **TV-side control service**; the phone APK cannot issue privileged Android key events or HDMI/window operations on its own. Avoid dependence on permanent Wi-Fi ADB or Termux for everyday controls.
- The phone APK and TV service must be version-compatible, with friendly offline states, disconnect recovery and pairing revocation. The original N500 physical remote always stays usable.
- Deliver a working pair: preview TV APK + companion phone APK, with tests on-device, before publishing stable builds.

### 3.1 Local phone configuration
- Same-Wi-Fi **LAN-only** web UI, accessible via QR/link displayed in TV Settings, inspired by upstream's existing phone wallpaper upload flow.
- Pairing code or QR authentication, expiring session and explicit permission; avoid unsecured anonymous settings endpoints or Internet exposure.
- Change module toggles, wallpaper, layout, dock, favourites, source inclusion, row order and presets from phone with live preview and Apply/Undo.
- Optional phone-as-remote controls: directional keys, OK, Back, Home, app launch, HDMI input switch **only where supported**.
- TV must remain fully configurable from remote alone; phone is enhancement, never mandatory.

### 3.2 Projector remote / focus button
- Preserve D-pad/OK/Back/Home and vendor volume, power and optical focus/autofocus by default.
- Investigate what **focus button** emits: normal Android KeyEvent, vendor key code, Linux input event, or handled entirely by projector firmware. A launcher *cannot* remap a key it never receives.
- If safely exposed: **optional** user-selected shortcut (open quick controls / settings / multi-view panel) with long-press or alternate gesture **only if original lens focus function remains reliable and recoverable**.
- If not exposed, use a configurable on-screen quick-access button plus an unassigned remote shortcut; do not promise physical focus remapping.
- Test with supported input diagnostics; do not request root or disable hardware control services.

## Phase 4 — Built-in multi-view controller + HDMI experiments (P2/R&D)

**User preference: multi-view belongs inside Glass TV itself — no separately launched controller app.**
- Home menu, remote-friendly control panel and optional phone UI all share the same **Multi-View** settings.
- Configure Full Screen / Side by Side / PiP overlay / swapped primary-secondary / saved profiles (Game + video, HDMI + app, App + App).
- If supported: show input selection, choose installed app/source, position/size/opacity (where possible), focus switching, audio source and close/restore.
- IMPORTANT: **A launcher can orchestrate only what the Android window manager, involved apps, and the N500 firmware support.** It cannot freely embed arbitrary DRM streaming apps in its own views, steal HDMI pixels or create an OS-level compositing path by drawing rectangles.
- Android TV PiP requires OS capability and app support; third-party streaming apps must cooperate. HDMI1 must remain running in the background only if vendor hardware / TV Input framework permits access. Overlay/PiP while HDMI active may be impossible without vendor/system privileges.
- Start with a **read-only hardware capability audit**. Record Android version, `pm list features`, PiP/multi-window support, TV Input services, manufacturer HDMI activity, remote input events. Do **not** modify OS/disable HDMI packages until identified.
- Build a small proof-of-concept for **supported** App+App PiP/split and HDMI switching; only after confirmation attempt HDMI+App simultaneous video. No fake UI claiming video is playing.
- If direct HDMI PiP is inaccessible, ship the useful one-tap switcher / profiles and clearly mark unsupported compositions.
- Keep picture quality, latency, audio focus, CEC, input fallback and Home/Back behavior intact.

## Phase 5 — Polish and optional extras (P3)

- More configurable scenic themes, custom uploads, single-wallpaper lock, rotation interval, blur/tint/legibility controls.
- Dock pin/order, app categories, favourite groups, labels/icons, installed-app refresh.
- Startup behavior, ambient/screensaver controls, performance diagnostics, cache-clearing UI, reduced motion and accessibility.
- Optional clock, date, prayer/AQI placement and visibility, configurable Home screen presets.
- Documentation/tutorial and recovery instructions for phone-only owners.

## Delivery sequence and acceptance gates

| Milestone | Required acceptance |
|---|---|
| M0 Secure updater | Repeatable signing, compatible upgrade OR documented safe migration, rollback, smoke tests |
| M1 Mini weather | Original/mini/both/off switch; 3/5/7-day options; survives restart; no regression |
| M2 Layout editor | Per-module toggles + order, remote focus, presets, persists reboot |
| M3 Streaming discovery | Capability matrix from actual installed apps; no invented history/deep links |
| M4 Streaming UI | Real rows from compatible apps; per-app/row controls; fast scrolling |
| M5 Android phone APK + TV controller | GitHub-built installable phone APK, paired authenticated projector service, D-pad/OK/Back/Home and settings, original remote remains fully supported |
| M6 Focus shortcut | Only if Android exposes usable key and optical focus function is preserved |
| M7 Multi-view audit/POC | Hardware feasibility documented; supported app PiP/HDMI behavior demonstrated |
| M8 Multi-view UI | Integrated controls only for proven capabilities; explicit unsupported states |
| M9 Stabilize/release | Cold boot, Home, Back, apps, HDMI, Wi-Fi ADB, screen idle, error/offline, rollback verified |

## Tests and evidence

- Record screenshots/video of home, settings, forecast, streaming module and any PiP/HDMI experiment.
- Verify remote navigation and no focus traps, no frozen display, no app-closing side effects, and memory/network overhead on the N500.
- Measure UI smoothness and stability under 0 / few / many installed apps and 0 / hundreds of posters.
- Test offline, unavailable feed, disabled apps, wrong permission, reboot, orientation/resolution, clock/location issues.
- Track upstream changes deliberately (avoid blindly rebasing on a new release).
- Current priority: **M0, M1, M2** while running a non-invasive capability audit for M3/M7.
